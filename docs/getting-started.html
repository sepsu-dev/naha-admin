Getting Started

Installation, local setup, and folder structure.

Follow the simple steps below to set up and run NahaAdmin on your local machine.

1. Cloning the Repository

git clone https://github.com/sepsu-dev/naha-admin.git
cd naha-admin

2. Open in Your Browser

Double-click index.html in the project folder, or use your browser's Open File command. No local server, package installation, or build step is required.

  • index.html — landing page.
  • demo/index.html — dashboard and component examples.
  • docs/index.html — documentation.

Keep the project folders together so relative asset paths work. Some examples load third-party assets from CDNs and need an internet connection.

3. Creating New Pages (Blueprints)

To build new views, duplicate one of our clean pre-configured templates inside demo/:

demo/starter.html

Contains header navbar, sidebar navigation, footer, and a starter container ready for your custom widgets and cards.

demo/blank.html

Minimal page scaffolding with empty canvas, suitable for bespoke application modules and custom views.

4. Folder Structure

naha-admin/
├── assets/         # App assets (CSS, JS, images, icons)
│   ├── plugins/    # Bundled libraries (Bootstrap 5.3.8, jQuery, SimpleBar, ECharts, etc.)
│   ├── images/     # Dashboard preview, avatars, and graphics
│   ├── scripts/    # Shared layout plus pages/ initializers
│   └── styles/     # Shared theme, docs, landing, and pages/ styles
├── demo/           # Dashboards, apps, and dedicated component examples
├── docs/           # Standalone multi-page documentation
└── index.html      # Landing & introduction page

5. Plugins & Vendors Reference

Core libraries are bundled under assets/plugins/. Advanced examples also use CDN assets and Google Fonts; those need internet access. System font fallbacks work without Google Fonts.

Plugin Purpose Directory
Bootstrap 5.3 Core UI grid, modals, alerts, utilities assets/plugins/bootstrap/
Phosphor Icons Icon fonts in six weights; examples load only the weights they use assets/plugins/phosphor/
SimpleBar Custom lightweight scrollbar for sidebars assets/plugins/simplebar/
NProgress Slim progress bar during page loading assets/plugins/nprogress/
DataTables & Grid.js Interactive tables with search & sorting Via CDN (cdn.datatables.net, unpkg.com/gridjs)
Editors, maps, notifications, drag and drop Quill, CKEditor, Summernote, Leaflet, Notyf, SortableJS, and flag icons Via CDN on the relevant demo pages

6. Asset order and editing

Load Bootstrap CSS, vendor CSS, NahaAdmin CSS, then page CSS. Load jQuery before naha-admin.min.js and jQuery plugins. Load each vendor before its page initializer. Keep page-only dependencies out of the shared layout.

Edit assets/styles/naha-admin.css and assets/scripts/naha-admin.js, then copy their contents to assets/styles/naha-admin.min.css and assets/scripts/naha-admin.min.js. The historical .min URLs are compatibility copies, not compressed builds. No build tool is required to use the template.

7. Demo boundaries

Dashboard numbers and app content are sample data. Auth forms validate in the browser but do not authenticate users, create accounts, or send email. Connect your own backend, add server-side validation and authorization, and replace demo actions before deploying an application.

8. Reusing a component

Open Live Preview, then choose a page under Components. Copy the component markup and its matching CSS/JS references. For example, Alert Dialog uses Bootstrap modal behavior plus these page assets:

<!-- In the head, after Bootstrap and NahaAdmin CSS -->
<link rel="stylesheet" href="../assets/styles/pages/components.css">

<!-- At the end of body, after Bootstrap and shared layout scripts -->
<script src="../assets/scripts/pages/components.js"></script>

Paths above assume an HTML file in demo/. Keep labels, IDs, aria-*, and data-bs-* attributes together; use unique IDs when repeating examples. Page handlers may depend on specific IDs. Bootstrap owns modal/offcanvas focus and dismissal. These are Bootstrap HTML examples, not React components or shadcn API-compatible packages.

Attachments remain local (5 MB limit). Chat replies, history, trace output, and questionnaire results are demos; no upload or AI service is included. In-memory edits reset on reload. See Browser Support for modern API requirements.
